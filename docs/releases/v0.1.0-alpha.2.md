# CoderPolice v0.1.0-alpha.2

Status: release candidate. No package-registry publication is part of this release.

## What changed

This alpha records the public project rename from **Agentic Engineering Conformance** to **CoderPolice**.

**Agentic Engineering Conformance** remains the technical descriptor for the benchmark. **CoderPolice** is the public project name.

The primary tagline is:

> Okay, but prove it.

The GitHub repository is now:

`https://github.com/deevyanshoo/coderpolice`

The Python distribution metadata is now `coderpolice` at version `0.1.0a2`. The import namespace remains `agentic_conformance` to avoid unnecessary breaking churn.

## Historical continuity

`v0.1.0-alpha.1` remains unchanged under the original technical working title.

This release does not rewrite:

- historical experiment bundles;
- scenario identifiers;

## Scope carried forward from alpha.1

CoderPolice remains a research alpha with:

- six provisional domains: AUTH, MUT, COMP, REV, INV, and REC;
- six deterministic synthetic reference scenarios;
- separate functional and control outcomes;
- guarded-versus-behavioral pass semantics;
- explicit evidence provenance and stored-evidence rescoring;
- Codex and Claude Code adapters for AUTH-001; and
- experimental neutral Windows Task Scheduler execution.

## Limitations and non-claims

- The six-domain taxonomy remains provisional.
- Real-host integration currently covers AUTH-001, not all six domains.
- Small host samples are not comparative performance evidence.
- The neutral runner remains Windows-specific in the current alpha.
- CoderPolice is not a certification program, security boundary, leaderboard, or proof that a coding-agent stack is safe in general.
- No novelty or legal priority claim is made for the name, taxonomy, workflow concepts, evidence model, review model, DAG patterns, invalidation patterns, tracing, or orchestration ideas.
